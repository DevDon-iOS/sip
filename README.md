# Sip

Sip은 사용자가 정한 **낮잠 가능 시간대** 안에서 실제로 잠든 시간을 찾고, 기상 후 상태와 낮잠 추세를 돌아보게 하는 iPhone·Apple Watch 앱입니다.

이 앱의 역할은 “몇 분 자야 한다”고 지시하는 것이 아닙니다. 다음 세 가지에 집중합니다.

- 실제로 몇 분 잠들었는지 기록합니다.
- 어떤 신호와 출처로 판단했는지 보여줍니다.
- 잠에서 깬 뒤 에너지·집중·기분이 어떤지 사용자가 직접 남기게 합니다.

## 핵심 경험

1. 사용자가 `13:00–14:00`처럼 낮잠을 잘 수 있는 시간대를 정합니다.
2. 종료 시각에 알람을 울릴지는 설정에서 선택합니다.
3. Sip은 시간대 안에서 사용할 수 있는 신호를 확인하고, 잠든 구간이 발견될 때만 낮잠 기록을 만듭니다.
4. Apple 건강이 제공한 수면 기록이 있으면 병합하고, 없으면 `Sip 추정`임을 명확히 표시합니다.
5. 기상 후 에너지·집중·기분을 숫자 없는 슬라이더로 기록합니다.
6. 기록이 쌓이면 잠든 시간, 수면 신호와 기상 후 상태를 부드러운 곡선과 의미색으로 보여줍니다.

## 측정 원칙

- Apple Watch 수면 단계 알고리즘을 복제하거나 의료적 수면 질 점수를 만들지 않습니다.
- Apple 건강 데이터, Sip 추정, 신호 부족 상태를 시각적으로 구분합니다.
- 짧은 낮잠에 Apple 수면 단계가 없더라도 단계를 임의로 생성하지 않습니다.
- `낮잠 가능 시간대`는 관찰 문맥이며, 공개 API로 시간대 전체의 센서를 계속 점유할 수 있다고 약속하지 않습니다.
- 종료 알람이 켜진 경우 공개 API가 허용하는 범위에서 종료 전 최대 30분의 Smart Alarm 실행을 검토합니다.
- 기록이 발견되지 않은 경우 실패 메시지 대신 빈 상태를 보여주고, 사용자가 기록을 추가하거나 수정할 수 있게 합니다.

## 상태 입력과 추세

에너지·집중·기분은 내부적으로 `0...1` 연속값으로 저장합니다. 사용자에게 숫자나 점수는 노출하지 않습니다.

- 슬라이더 양 끝에는 `기운이 없어요–활력이 있어요`처럼 의미를 표시합니다.
- 드래그 중 thumb와 햅틱으로 즉시 반응하고, 손을 놓으면 부드럽게 안정됩니다.
- 추세는 색상과 곡선으로 표현하되, 색만으로 의미를 구분하지 않습니다.
- 관찰된 변화만 보여주며 원인이나 효과를 단정하지 않습니다.

## 화면 기준

- iPhone 기준: iPhone 13 mini `375×812`
- iPhone 적응형 QA: iPhone SE `375×667`, iPhone 15 Pro `393×852`
- Apple Watch 기준: 40mm `162×197`
- Apple Watch 적응형 QA: 45mm `198×242`
- iPhone과 Watch 화면은 Figma Product Design 한 페이지에서 관리합니다.

## 현재 상태

| 영역 | 상태 |
| --- | --- |
| 제품 흐름·화면·컴포넌트 V2 | 설계 완료 |
| 낮잠 가능 시간대와 선택형 종료 알람 | 제품 요구사항 확정 |
| Apple 건강 수면 기록 병합 | 설계 완료, 구현 검증 필요 |
| 짧은 낮잠 Sip 추정 모델 | 방향 정의, 실제 기기 데이터 검증 필요 |
| 상태 슬라이더와 추세 | 설계 완료, 구현 필요 |
| iPhone·Watch 기존 프로토타입 | 저장소에 존재, V2 설계와 동기화 필요 |

현재 저장소의 앱 코드는 초기 프로토타입입니다. Figma와 문서가 정의한 자동 감지 동작이 구현됐다고 간주하지 않습니다.

## 기술 구성

- Swift, SwiftUI
- HealthKit
- WatchKit extended runtime session
- WatchConnectivity
- iOS, watchOS

중요한 Watch 기록은 즉시 연결이 필요한 `sendMessage`에만 의존하지 않고 로컬 보관과 재시도 가능한 전송을 사용합니다.

## 개발 원칙

- 측정값, 사용자 입력과 추정값을 구분합니다.
- HealthKit 권한 거부나 Watch 미사용이 불이익으로 이어지지 않게 합니다.
- 건강 데이터를 최소 권한으로 요청하고 가능한 처리는 기기에서 수행합니다.
- 연결 끊김, 앱 재실행과 시간대 변경에도 원본 기록이 유실되지 않게 합니다.
- 데이터가 부족할 때는 품질이나 효과를 단정하지 않습니다.
