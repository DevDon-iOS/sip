# Sip 제품 요구사항 문서

| 항목 | 내용 |

| 대상 플랫폼 | iOS, watchOS |

## 1. 제품 요약

Sip은 Apple Watch에서 낮잠 측정을 시작하고, 측정 결과를 iPhone과 Apple 건강에 기록해 낮잠 습관을 확인할 수 있도록 돕는 앱입니다.

야간 수면 전체를 분석하는 범용 수면 앱이 아니라, 짧고 불규칙해 기존 수면 추적 경험에서 놓치기 쉬운 낮잠에 집중합니다. MVP에서는 사용자가 직접 측정을 시작하고 종료하는 방식으로 신뢰할 수 있는 기록을 만드는 것을 우선합니다.

## 2. 배경과 문제 정의

### 2.1 배경

- Apple Watch는 수면 측정을 지원하지만 충전, 착용감, 생활 습관 등의 이유로 밤에 Watch를 착용하지 않는 사용자가 있습니다.
- 낮잠은 야간 수면보다 시작 시각과 길이가 불규칙하며, 사용자가 의도적으로 기록하고 싶어도 낮잠만을 위한 명확한 측정 흐름이 부족합니다.
- Apple 건강의 수면 데이터에는 별도의 낮잠 유형이 없으므로, 모든 수면 샘플을 시간대만으로 분류하면 야간 수면이나 다른 앱의 기록을 낮잠으로 오인할 수 있습니다.

### 2.2 해결할 문제

사용자는 다음 질문에 신뢰할 수 있는 답을 얻기 어렵습니다.

- 오늘 낮잠을 얼마나 잤는가?
- 최근 낮잠 시간과 빈도는 어떻게 변하고 있는가?
- 측정한 낮잠이 Apple 건강에 정상적으로 기록됐는가?
- Watch와 iPhone의 연결이 끊겨도 기록이 남아 있는가?

## 3. 제품 비전

낮잠이 필요할 때 가장 빠르게 측정을 시작하고, 깨어난 뒤 가장 쉽게 기록을 확인할 수 있는 Apple 생태계의 낮잠 전용 앱이 됩니다.

## 4. 목표 사용자

### 4.1 주요 사용자

- 밤에는 Apple Watch를 착용하지 않지만 낮잠은 기록하고 싶은 사용자
- 교대 근무, 육아, 학업 또는 업무 중 짧은 수면을 자주 취하는 사용자
- 낮잠 시간과 빈도를 관리해 생활 리듬을 돌아보고 싶은 사용자

### 4.2 사용자 요구

- Watch에서 몇 번의 탭만으로 측정을 시작하고 싶다.
- 측정 중 화면이 꺼지거나 연결이 끊겨도 기록을 잃고 싶지 않다.
- iPhone에서 낮잠 기록만 분리해 보고 싶다.
- 어떤 건강 데이터가 저장되고 사용되는지 알고 싶다.

## 5. 제품 목표와 성공 기준

### 5.1 목표

1. 낮잠 시작과 종료 과정을 단순하게 만든다.
2. 측정 기록을 로컬에 먼저 보존하고 Watch–iPhone 전송 실패에도 복구할 수 있게 한다.
3. Sip에서 만든 낮잠 기록을 Apple 건강과 일관되게 동기화한다.
4. 낮잠 기록과 기본 통계를 이해하기 쉬운 형태로 제공한다.
5. 건강 데이터에 대한 최소 권한과 사용자 통제권을 보장한다.

### 5.2 MVP 성공 지표

| 지표 | 정의 | 초기 목표 |
| --- | --- | --- |
| 측정 완료율 | 시작된 낮잠 세션 중 정상 종료·저장된 비율 | 95% 이상 |
| 동기화 성공률 | Watch에서 생성된 세션 중 iPhone에 최종 반영된 비율 | 99% 이상 |
| 기록 유실률 | 시작됐으나 어떤 기기에도 복구 가능한 기록이 남지 않은 비율 | 0% 목표 |
| 측정 시작 시간 | 앱 실행 후 측정 시작까지 걸리는 시간 | 중앙값 10초 이내 |
| 비정상 종료 없는 세션 비율 | 크래시 없이 완료된 측정 세션 비율 | 99.5% 이상 |

지표 수집 방식은 개인정보 보호 원칙과 사용자 동의 범위 안에서 별도로 확정해야 합니다.

## 6. 범위

### 6.1 MVP 포함 범위

- Apple Watch에서 낮잠 측정 시작, 진행 상태 확인, 종료
- 측정 세션의 시작·종료 시각과 지속 시간 기록
- Watch 로컬 저장 및 iPhone으로의 재시도 가능한 전송
- HealthKit 권한 요청과 Sip이 생성한 수면 샘플 저장
- iPhone에서 낮잠 기록 목록과 상세 정보 확인
- 기간별 낮잠 횟수, 총 낮잠 시간, 평균 낮잠 시간 제공
- 기록 수정 및 삭제 시 Sip 내부 기록과 HealthKit 기록의 일관성 유지
- 권한 거부, 연결 끊김, 전송 지연, 빈 기록 상태 안내

### 6.2 MVP 제외 범위

- 의료적 진단 또는 치료 조언
- 야간 수면 전체 분석 및 기존 수면 앱 대체
- 검증되지 않은 수면 단계 판정
- 근거가 정의되지 않은 수면 질 점수
- 완전 자동 낮잠 감지
- 소셜 기능, 친구 비교, 공개 순위
- 확정되지 않은 계정 기반 클라우드 동기화

## 7. 핵심 사용자 흐름

### 7.1 최초 설정

1. 사용자가 iPhone 앱에서 Sip의 목적과 데이터 사용 안내를 확인한다.
2. 앱이 기능 수행에 필요한 HealthKit 읽기·쓰기 권한을 요청한다.
3. 권한 결과를 설명하고, 거부된 경우 설정 이동 방법과 제한되는 기능을 안내한다.
4. Apple Watch 앱 설치 및 연결 상태를 확인한다.

### 7.2 낮잠 측정

1. 사용자가 Watch 앱을 열고 `낮잠 시작`을 누른다.
2. 앱은 시작 시각과 고유 세션 ID를 즉시 로컬에 저장한다.
3. 측정 화면은 경과 시간과 종료 동작을 명확히 보여준다.
4. 사용자가 `낮잠 종료`를 누르면 종료 확인 후 세션을 완료한다.
5. 완료된 세션은 Watch에 보존되고 iPhone 전송을 시도한다.
6. iPhone은 중복 여부를 확인한 뒤 기록을 저장하고 HealthKit에 반영한다.

### 7.3 기록 확인

1. 사용자가 iPhone 앱의 기록 또는 분석 화면을 연다.
2. 최근 낮잠과 날짜별 지속 시간을 확인한다.
3. 기간을 선택해 횟수, 총시간, 평균 시간을 확인한다.
4. 기록을 수정하거나 삭제할 경우 영향을 받는 HealthKit 데이터에 대해 안내받는다.

### 7.4 오류 복구

1. Watch와 iPhone 연결이 끊기면 Watch가 완료 세션을 로컬에 유지한다.
2. 연결이 복구되면 대기 중인 세션을 재전송한다.
3. 동일한 세션 ID가 다시 도착해도 중복 저장하지 않는다.
4. 최종 동기화에 실패하면 사용자에게 상태와 재시도 방법을 보여준다.

### 8.1 Apple Watch 측정

| WATCH-003 | 화면이 꺼지거나 앱이 비활성화돼도 세션 상태를 복구할 수 있어야 한다. | Must |
| WATCH-004 | 사용자는 진행 중인 세션의 경과 시간을 확인할 수 있어야 한다. | Must |
| WATCH-005 | 종료 동작은 실수로 인한 종료를 줄이는 확인 단계를 제공해야 한다. | Should |
| WATCH-006 | 앱 재실행 시 진행 중이거나 전송 대기 중인 세션을 복구해야 한다. | Must |

### 8.2 기록 및 동기화

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| SYNC-001 | 각 세션은 기기 간에 유지되는 고유 ID를 가져야 한다. | Must |
| SYNC-002 | 중요한 기록 전송은 iPhone의 즉시 연결 상태에만 의존하지 않아야 한다. | Must |
| SYNC-003 | 전송은 재시도 가능해야 하며 동일 세션의 중복 저장을 방지해야 한다. | Must |
| SYNC-004 | 부분 전송 또는 앱 종료 후에도 마지막 확정 상태를 복구해야 한다. | Must |
| SYNC-005 | 사용자는 동기화 대기·완료·실패 상태를 확인할 수 있어야 한다. | Should |

구현 시 `WCSession.sendMessage`만으로 중요한 세션을 전달하지 않고, 페이로드 성격에 맞는 지속성 전송 방식과 로컬 큐를 사용해야 합니다.

### 8.3 HealthKit

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| HEALTH-001 | 앱은 사용 목적을 설명한 뒤 필요한 수면 데이터 권한만 요청해야 한다. | Must |
| HEALTH-002 | Sip에서 완료된 세션을 HealthKit 수면 샘플로 저장할 수 있어야 한다. | Must |
| HEALTH-003 | Sip이 생성한 샘플과 외부 앱이 생성한 샘플을 구분해야 한다. | Must |
| HEALTH-004 | 권한이 없더라도 가능한 로컬 기록은 보존하고 제한 사항을 알려야 한다. | Must |
| HEALTH-005 | 기록 수정·삭제 시 앱 내부 데이터와 Sip이 생성한 HealthKit 샘플 간 불일치를 방지해야 한다. | Must |

HealthKit에는 별도의 낮잠 카테고리가 없으므로 시간대만으로 모든 수면 샘플을 낮잠으로 분류하지 않습니다. MVP 분석은 Sip에서 사용자가 시작한 세션을 기준으로 합니다.

| IOS-003 | 선택 기간의 낮잠 횟수, 총시간, 평균 시간을 계산해야 한다. | Must |

| IOS-006 | 사용자는 자신이 만든 기록을 수정하거나 삭제할 수 있어야 한다. | Should |

## 9. 데이터 모델 초안

### NapSession

| 필드 | 설명 |
| --- | --- |
| `id` | 기기 간 중복 방지를 위한 고유 식별자 |
| `startDate` | 낮잠 시작 시각 |
| `endDate` | 낮잠 종료 시각. 진행 중에는 비어 있을 수 있음 |
| `duration` | 종료 후 계산되는 지속 시간 |
| `sourceDevice` | 세션을 시작한 기기 정보 |
| `status` | `inProgress`, `completed`, `pendingSync`, `synced`, `failed` |
| `healthKitIdentifier` | Sip이 저장한 HealthKit 샘플을 연결하기 위한 식별 정보 |
| `createdAt` | 최초 생성 시각 |
| `updatedAt` | 마지막 변경 시각 |

시간은 절대 시각으로 저장하고 사용자 표시 시 현재 로캘, 캘린더, 시간대를 적용합니다. 기기 시간대 변경 후에도 원본 시점을 잃지 않아야 합니다.

## 10. 비기능 요구사항

### 10.1 신뢰성

- 측정 시작 이벤트는 네트워크나 iPhone 연결 여부와 관계없이 Watch에 먼저 저장합니다.
- 동기화는 멱등성을 보장하며 중복 전송을 정상 흐름으로 처리합니다.
- 충전 부족, 앱 종료, 연결 끊김 이후에도 완료된 기록을 복구할 수 있어야 합니다.

### 10.2 개인정보 보호와 보안

- HealthKit 데이터는 기능에 필요한 최소 범위만 요청합니다.
- 건강 데이터와 인증 정보를 로그에 남기지 않습니다.
- MVP는 서버 없이 동작 가능한 로컬 우선 구조를 기본 가정으로 합니다.
- 서버 동기화를 도입할 경우 저장 목적, 보존 기간, 삭제 방법, 암호화와 동의 흐름을 별도로 정의합니다.

### 10.3 접근성

- Dynamic Type, VoiceOver, 충분한 대비와 터치 영역을 지원합니다.
- 측정 시작·종료 상태를 색상만으로 전달하지 않습니다.
- 중요한 동작과 오류에는 명확한 접근성 레이블과 상태 값을 제공합니다.

### 10.4 성능과 배터리

- 측정 중 불필요한 센서 샘플링과 화면 갱신을 최소화합니다.
- Watch 배터리 사용량을 측정하고 허용 기준을 정한 뒤 자동 감지 범위를 결정합니다.
- 장시간 실행과 백그라운드 상태에서 세션 지속성을 실제 기기로 검증합니다.

## 11. 화면 및 상태 요구사항

### Watch

- 측정 전: 낮잠 시작, 연결·권한 상태
- 측정 중: 경과 시간, 종료
- 완료: 측정 결과, 전송 상태
- 복구: 진행 중 세션 또는 전송 대기 세션 복원
- 오류: 저장 실패, 권한 제한, 동기화 지연

### iPhone

- 온보딩 및 HealthKit 권한 안내
- 홈: 최근 낮잠과 측정 상태 요약
- 기록: 낮잠 목록과 상세
- 분석: 기간별 횟수, 총시간, 평균 시간
- 설정: 건강 연동 상태, 데이터 관리, 개인정보 안내

## 12. MVP 인수 조건

- [ ] 사용자가 Watch에서 낮잠을 시작하고 종료할 수 있다.
- [ ] 측정 중 Watch 앱을 닫았다가 다시 열어도 진행 상태가 복구된다.
- [ ] iPhone이 연결되지 않은 상태에서 종료한 기록이 연결 복구 후 전송된다.
- [ ] 같은 기록이 여러 번 전달돼도 한 번만 저장된다.
- [ ] Sip이 생성한 낮잠이 HealthKit에 저장되고 앱에서 다시 식별된다.
- [ ] HealthKit 권한을 거부해도 앱이 종료되지 않고 제한 상태를 안내한다.
- [ ] iPhone에서 최근 기록과 기간별 횟수·총시간·평균 시간을 확인할 수 있다.
- [ ] 기록이 없거나 동기화에 실패한 상태가 명확히 표시된다.
- [ ] 사용자가 만든 기록을 삭제할 수 있고 관련 데이터 처리 결과를 확인할 수 있다.
- [ ] 실제 Apple Watch에서 화면 꺼짐, 연결 끊김, 재연결, 앱 재실행 시나리오를 검증한다.

## 13. 리스크와 대응 방향

| 리스크 | 영향 | 대응 방향 |
| --- | --- | --- |
| HealthKit에 낮잠 전용 유형이 없음 | 야간 수면과 낮잠 오분류 | Sip이 시작한 고유 세션만 MVP 낮잠 분석 대상으로 사용 |
| Watch–iPhone 연결 불안정 | 기록 지연 또는 유실 | Watch 로컬 저장, 지속성 전송, 재시도, 중복 방지 |
| 자동 감지 정확도 부족 | 잘못된 낮잠 기록과 신뢰 하락 | MVP는 수동 시작·종료, 자동 감지는 별도 검증 후 도입 |
| 수면 질 점수 근거 부족 | 오해를 유발하는 지표 제공 | 점수 정의와 입력 신호가 검증되기 전까지 제외 |
| 백그라운드 실행 제약 | 측정 중단 가능성 | watchOS 수명 주기와 적합한 세션 API 검토 및 실제 기기 검증 |
| 배터리 소모 | Watch 착용 지속성 저하 | 최소 샘플링, 장시간 측정, 저전력 상태 테스트 |

## 14. 단계별 계획

### Phase 1: 신뢰할 수 있는 수동 측정

- Watch 측정 시작·종료
- 로컬 세션 보존
- iPhone 지속성 동기화
- HealthKit 저장
- 기본 기록 목록

### Phase 2: 기록 관리와 분석

- 기록 수정·삭제
- 기간별 통계
- 권한·동기화 상태 개선
- 접근성 및 실제 기기 안정성 검증

### Phase 3: 측정 보조 기능 검토

- 낮잠 종료 알림 또는 햅틱
- 자동 종료 제안
- 자동 감지 가능성 검증
- 수면 질 지표의 데이터 근거 검토

## 15. 미결정 사항

다음 항목은 구현 전에 제품 결정을 확정해야 합니다.

1. MVP가 완전 수동 측정만 지원할지, 타이머 기반 자동 종료를 포함할지
2. 권장 낮잠 시간 또는 알람·햅틱 기능을 제공할지
3. 낮잠으로 인정할 최소·최대 지속 시간을 둘지
4. 진행 중 세션에 watchOS의 어떤 장기 실행 방식을 사용할지
5. 수면 질 점수를 제공할 경우 어떤 신호와 검증 기준을 사용할지
6. 계정과 서버 기반 동기화가 필요한지, 로컬·HealthKit만 사용할지
7. 지원할 최소 iOS, watchOS 및 Apple Watch 기기 범위
8. 사용자 행동 분석을 수집할지와 개인정보 동의 방식을 어떻게 구성할지

## 16. 검증 계획

### 자동 검증

- 세션 지속 시간 계산과 시간대 변경 테스트
- 동기화 중복 제거 및 재시도 테스트
- 진행 중·완료·실패 상태 전이 테스트
- HealthKit 저장 데이터 매핑 테스트
- 기간별 통계 계산 테스트

### 실제 기기 검증

- Watch 화면 꺼짐과 앱 백그라운드 전환
- iPhone 연결 끊김 상태에서 측정 종료 후 재연결
- Watch 또는 iPhone 앱 강제 종료 후 복구
- HealthKit 권한 허용·거부·변경
- 저전력 및 배터리 부족 상태
- 시간대 변경과 자정 전후 낮잠

시뮬레이터와 자동 테스트 성공은 HealthKit, Watch 연결, 백그라운드 실행의 실제 기기 동작을 증명하지 않으므로 별도로 보고합니다.
