# Sip 제품 요구사항 문서

| 항목 | 내용 |
| --- | --- |
| 제품명 | Sip |
| 문서 상태 | 출시 버전 초안 v0.2 |
| 작성일 | 2026-08-12 |
| 대상 플랫폼 | iOS, watchOS |
| 최소 지원 버전 | iOS 18.0, watchOS 10.0 |
| 핵심 가치 | 낮잠 측정, 컨디션 체크인, 개인화 피드백 |

## 1. 제품 정의

Sip은 낮잠 시간을 기록하는 타이머가 아니라, **낮잠이 사용자의 하루 컨디션에 어떤 영향을 주었는지 알려주는 개인화 낮잠 코치**입니다.

사용자는 낮잠 전·직후·하루 종료 시점에 에너지, 집중, 기분을 간단히 평가합니다. Sip은 이 자가 평가를 핵심 신호로 사용하고, 사용자가 허용한 경우에만 HealthKit의 수면과 심혈관 관련 지표를 보조 신호로 결합합니다.

피드백은 의료적 판단이나 인과관계의 단정이 아닙니다. 개인 기록에서 반복적으로 관찰된 변화와 연관성을 설명하고, 근거가 부족한 경우에는 이를 명확히 밝힙니다.

## 2. 해결할 문제

- Apple 건강의 수면 추적 경험은 짧고 불규칙한 낮잠을 의도적으로 시작하고 관리하기에 충분하지 않습니다.
- 낮잠 시간을 기록하더라도 그것이 실제 에너지, 집중, 기분과 하루 전체 컨디션에 도움이 됐는지 알기 어렵습니다.
- 일반적인 “20분 낮잠이 좋다”는 조언은 개인의 생활 리듬, 시간대와 야간 수면 상태를 반영하지 못합니다.
- 사용자는 낮잠이 효과적이었던 조건과 오히려 컨디션을 흐트러뜨린 조건을 자신의 데이터로 이해하고 싶어 합니다.

## 3. 제품 원칙

1. **자가 평가 우선:** HealthKit 권한이 없어도 핵심 경험이 동작해야 합니다.
2. **개인 패턴 우선:** 일반론보다 사용자의 반복 기록을 우선합니다.
3. **관찰과 추론 분리:** 측정값, 사용자 응답, 계산 결과, 추정 피드백을 구분합니다.
4. **낮은 입력 부담:** 체크인은 기본 3문항, 약 10초 안에 완료할 수 있어야 합니다.
5. **로컬 우선과 최소 권한:** 건강 데이터는 필요한 범위만 요청하고 가능한 처리는 기기에서 수행합니다.
6. **기록 유실 방지:** Watch 연결이나 HealthKit 저장 실패가 낮잠·체크인 원본의 유실로 이어지지 않아야 합니다.

## 4. 목표 사용자

- 밤에는 Apple Watch를 착용하지 않지만 낮잠은 기록하고 싶은 사용자
- 업무, 학업, 육아, 교대 근무 중 낮잠이 실제 회복에 도움이 되는지 알고 싶은 사용자
- 자신의 최적 낮잠 길이와 시간대를 찾고 싶은 사용자
- 야간 수면과 낮잠의 관계를 함께 돌아보고 싶은 사용자

## 5. 출시 범위

### 5.1 플랫폼 기준

- iPhone 앱의 minimum deployment target은 **iOS 18.0**입니다.
- Apple Watch 앱의 minimum deployment target은 **watchOS 10.0**입니다.
- 더 높은 OS 버전에서만 제공되는 API는 availability 확인과 대체 동작을 제공해야 합니다.

### 5.2 포함 기능

- iPhone 온보딩, 개인정보 안내, HealthKit 권한 관리
- 낮잠 전 컨디션 체크인
- Apple Watch와 iPhone에서 낮잠 시작, 권장 시간 선택, 진행 확인, 종료
- Watch 로컬 저장과 iPhone 지속성 동기화
- 낮잠 직후 컨디션 체크인
- 하루 종료 컨디션 체크인과 알림
- HealthKit 수면 샘플 저장
- 선택적으로 허용된 HealthKit 보조 지표 조회
- 오늘의 낮잠 효과 피드백
- 낮잠 상세 기록과 컨디션 변화 표시
- 누적 개인 패턴, 권장 길이·시간대와 주의 패턴
- 체크인·HealthKit·동기화 데이터의 수정과 삭제
- 권한 거부, 오프라인, 기록 부족, 동기화 실패 상태

### 5.3 출시 초안에서 제외

- 의료적 진단, 치료 또는 질환 예측
- 검증되지 않은 수면 단계 판정
- 근거 없는 단일 “수면 질 점수”
- 사용자의 확인 없는 완전 자동 낮잠 기록
- 소셜 비교와 공개 순위

## 6. 핵심 사용자 흐름

### 6.1 최초 설정

1. 사용자가 Sip의 목적과 피드백 원리를 확인합니다.
2. 앱은 자가 평가가 핵심이며 HealthKit은 선택적 보조 신호임을 설명합니다.
3. 사용자가 수면 데이터 읽기·쓰기와 선택 보조 지표별 권한을 결정합니다.
4. Apple Watch 설치·연결 상태와 알림 시간을 확인합니다.
5. 기본 낮잠 목표 시간과 하루 종료 체크인 시간을 설정합니다.

### 6.2 낮잠 전

1. 사용자가 현재 에너지, 집중, 기분을 각각 1~5로 평가합니다.
2. 선택적으로 “졸림”, “피로”, “스트레스”, “카페인”, “운동 후” 등의 맥락 태그를 추가합니다.
3. Sip은 최근 기록과 현재 시각을 바탕으로 권장 낮잠 길이를 제안합니다.
4. 데이터가 부족하면 개인화 추천이 아니라 일반 범위임을 표시합니다.

### 6.3 측정

1. 사용자가 Apple Watch 또는 iPhone에서 낮잠을 시작합니다.
2. 세션 ID와 시작 시각을 Watch 로컬에 즉시 저장합니다.
3. Watch는 경과 시간과 설정한 목표 시간을 보여줍니다.
4. 목표 시간이 되면 햅틱 또는 알림을 제공합니다.
5. 사용자가 종료하면 세션을 확정하고 iPhone 전송을 시도합니다.

### 6.4 낮잠 직후

1. 사용자가 회복감, 에너지, 집중, 기분을 간단히 평가합니다.
2. Sip은 낮잠 전후 변화를 즉시 보여줍니다.
3. HealthKit 및 동기화 상태를 함께 표시합니다.
4. 입력을 건너뛴 경우 나중에 기록에서 보완할 수 있습니다.

### 6.5 하루 종료

1. 설정한 시간에 하루 컨디션 체크 알림을 제공합니다.
2. 사용자가 오늘 전체 에너지, 집중, 기분과 밤 수면 예상 방해 여부를 평가합니다.
3. Sip은 낮잠 직후 효과와 하루 종료 상태를 구분해 분석합니다.
4. 오늘의 낮잠이 전반적인 컨디션과 보인 관계를 요약합니다.

### 6.6 누적 피드백

1. 사용자가 인사이트 화면에서 데이터 축적 상태를 확인합니다.
2. 충분한 기록이 쌓이면 길이, 시작 시간대, 이전 야간 수면과 컨디션 변화의 연관성을 보여줍니다.
3. 효과가 반복된 패턴은 “도움이 된 경향”, 불리한 패턴은 “주의할 경향”으로 표현합니다.
4. 사용자는 분석 근거가 된 기록과 보조 지표를 확인할 수 있습니다.

## 7. 컨디션 측정 모델

### 7.1 핵심 자가 평가

모든 기본 항목은 1~5 척도를 사용하며 양 끝의 의미를 문구로 함께 표시합니다.

| 시점 | 필수 항목 | 선택 항목 |
| --- | --- | --- |
| 낮잠 전 | 에너지, 집중, 기분 | 졸림·피로·스트레스 등 맥락 태그 |
| 낮잠 직후 | 회복감, 에너지, 집중, 기분 | 수면 관성, 방해 요인 태그 |
| 하루 종료 | 전체 에너지, 집중, 기분 | 밤 수면 방해 우려, 자유 메모 |

### 7.2 HealthKit 보조 신호

사용자 권한과 기기 지원 범위에서 다음 신호를 검토합니다.

- 이전 야간 수면 시간과 종료 시각
- 심박수와 안정 시 심박수
- 심박 변이도(HRV)
- Apple Watch가 제공하는 사용 가능한 수면 관련 샘플

각 신호는 누락될 수 있으며 자가 평가를 대체하지 않습니다. 지원되지 않거나 권한이 없는 지표는 피드백 계산에서 제외하고 사용자에게 불이익을 주지 않습니다.

## 8. 피드백 체계

### 8.1 즉시 피드백

- 낮잠 지속 시간과 목표 대비 결과
- 낮잠 전후 에너지·집중·기분 변화
- 사용자가 직접 입력한 회복감
- HealthKit 저장과 기기 동기화 상태

예시: `24분 낮잠 후 에너지와 집중이 각각 2단계, 1단계 높아졌어요.`

### 8.2 일일 피드백

- 낮잠 직후 개선이 하루 종료 시점까지 유지됐는지 여부
- 늦은 시간 또는 긴 낮잠과 저녁 컨디션의 관계
- 이전 야간 수면 부족 상황에서의 낮잠 효과

예시: `직후 회복감은 높았고 저녁 에너지도 낮잠 전보다 높게 유지됐어요.`

### 8.3 누적 개인화 피드백

- 효과가 좋았던 낮잠 길이 범위
- 효과가 좋았던 시작 시간대
- 짧은 낮잠과 긴 낮잠의 컨디션 변화 비교
- 이전 야간 수면 상태별 낮잠 효과
- 수면 관성이나 저녁 컨디션 저하가 반복되는 조건

개인화 피드백은 최소 기록 수와 데이터 품질 기준을 충족한 경우에만 제공합니다. 기준 미달 시 `아직 패턴을 판단하기에 기록이 부족해요`라고 표시합니다.

### 8.4 표현 원칙

- `낮잠 때문에 좋아졌습니다` 대신 `낮잠 후 좋아지는 경향이 관찰됐습니다`라고 표현합니다.
- 표본 수와 비교 기간을 함께 표시합니다.
- 상충하는 신호와 누락된 데이터가 있으면 숨기지 않습니다.
- 건강 이상을 진단하거나 의료행위를 권고하지 않습니다.

## 10. 데이터 모델 초안

### NapSession

`id`, `startDate`, `endDate`, `targetDuration`, `actualDuration`, `sourceDevice`, `status`, `healthKitIdentifier`, `createdAt`, `updatedAt`

### ConditionCheckIn

`id`, `napSessionId`, `phase(preNap/postNap/endOfDay)`, `energy`, `focus`, `mood`, `recovery`, `tags`, `note`, `recordedAt`, `updatedAt`

### HealthContextSnapshot

`id`, `napSessionId`, `sleepDuration`, `sleepEndDate`, `restingHeartRate`, `heartRateVariability`, `availableMetrics`, `capturedAt`

### Insight

`id`, `type(immediate/daily/pattern)`, `periodStart`, `periodEnd`, `evidenceCount`, `confidence(insufficient/emerging/established)`, `summary`, `supportingSignals`, `conflictingSignals`, `generatedAt`, `algorithmVersion`

모든 시각은 절대 시각으로 저장하고 표시 시 사용자의 현재 로캘, 캘린더와 시간대를 적용합니다.

## 11. 화면 구조

### iPhone

- 온보딩과 데이터 사용 안내
- HealthKit·알림 권한 설정
- 홈: 오늘 컨디션, 권장 낮잠, 최근 피드백
- 낮잠 전 체크인
- 측정 및 Watch 상태
- 낮잠 직후 체크인
- 오늘의 피드백
- 기록 목록과 낮잠 상세
- 개인 패턴과 데이터 축적 상태
- 설정, 권한, 데이터 내보내기·삭제

### Apple Watch

- 현재 컨디션과 권장 낮잠 요약
- 빠른 낮잠 전 체크인
- 측정 준비, 진행, 종료 확인
- 빠른 낮잠 직후 체크인
- 결과와 동기화 상태
- 진행 중·전송 대기 세션 복구

## 12. 알림

- 사용자가 설정한 낮잠 목표 시간 도달 알림
- 낮잠 종료 후 체크인 리마인드
- 사용자가 설정한 하루 종료 체크인 리마인드
- 동기화 실패 또는 권한 변경 안내

알림은 개별적으로 끌 수 있어야 하며, 반복적인 미응답 시 빈도를 자동으로 높이지 않습니다.

## 13. 개인정보와 안전

- 건강·자가 평가 데이터는 기본적으로 기기에서 처리합니다.
- 서버 동기화를 도입하면 저장 목적, 보존 기간, 암호화, 삭제와 동의를 별도로 정의합니다.
- 피드백 생성에 사용한 데이터 종류와 기간을 사용자가 확인할 수 있어야 합니다.
- 사용자는 기록, 체크인, 파생 인사이트를 삭제할 수 있어야 합니다.
- 민감한 값과 식별자는 로그와 분석 이벤트에 기록하지 않습니다.
- 진단, 치료, 약물 또는 질환 관련 조언을 제공하지 않습니다.
