# Sip 제품 요구사항 문서

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | V2 제품 설계 기준 v0.3 |
| 작성일 | 2026-08-12 |
| 대상 플랫폼 | iOS, watchOS |
| 최소 지원 버전 | iOS 18.0, watchOS 10.0 |
| 기준 기기 | iPhone 13 mini, Apple Watch 40mm |
| 핵심 가치 | 실제 잠든 시간, 측정 근거, 기상 후 상태와 추세 |

## 1. 제품 정의

Sip은 사용자가 정한 **낮잠 가능 시간대** 안에서 실제로 잠든 구간을 찾아 기록하고, 기상 후 상태와 장기 추세를 돌아보게 하는 앱이다.

Sip은 낮잠 길이를 강요하거나 에너지·집중·기분을 점수로 평가하지 않는다. 사용자가 알아야 할 핵심은 다음과 같다.

1. 몇 분 잠들었는가.
2. 어떤 신호와 출처로 판단했는가.
3. 잠에서 깬 뒤 본인의 상태는 어떠한가.

## 2. 해결할 문제

- 업무·학업·이동 중 낮잠은 시작 버튼을 누르고 정해진 시간만큼 자는 행위가 아닐 수 있다.
- 사용자가 쉴 수 있는 시간과 실제로 잠든 시간은 다르다.
- 짧은 낮잠에는 Apple 건강의 수면 단계가 제공되지 않을 수 있다.
- 근거가 약한 품질 점수, 효과 문구와 추천 시간은 혼동이나 압박을 만든다.
- 사용자는 동기화·전송 같은 시스템 상태보다 실제 기록과 추세를 더 궁금해한다.

## 3. 제품 원칙

1. **시간대와 수면 구간 분리:** 예약 범위를 실제 수면으로 간주하지 않는다.
2. **출처 표시:** `Apple 건강`, `Sip 추정`, `신호 부족`을 구분한다.
3. **점수 없음:** 수면 품질과 상태를 단일 숫자로 축약하지 않는다.
4. **사용자 판단 존중:** 추천보다 관찰과 수정 가능성을 우선한다.
5. **과장 없음:** 측정되지 않은 수면 단계나 인과관계를 만들지 않는다.
6. **낮은 입력 부담:** 기상 후 세 개의 연속형 슬라이더만으로 기록할 수 있다.
7. **로컬 우선:** 권한이 없거나 연결이 끊겨도 가능한 흐름은 계속된다.

## 4. Apple 수면 측정 조사와 적용 경계

### 4.1 확인된 Apple 방식

Apple의 2025 검증 문서에 따르면 Apple Watch 수면 단계 분류는 3축 가속도계 신호를 30초 epoch로 처리하고, 수면다원검사 데이터로 학습·검증한다. 단계는 깨어 있음, REM, 코어, 깊은 수면으로 구성되며 코어는 N1과 N2를 합친다.

iOS 18·watchOS 11부터 예약 밖 수면과 짧은 수면 감지가 개선됐지만, HealthKit에는 감지된 총 수면이 1–3시간인 경우 이진 수면·기상 기록이, 3시간을 넘는 경우 전체 수면 단계가 기록된다. 일반적인 1시간 미만 낮잠에는 Apple의 자동 수면 결과가 없을 수 있다.

### 4.2 Sip 적용 방향

- Apple 건강에 수면 샘플이 있으면 원본 출처와 단계를 그대로 사용한다.
- Apple 건강 결과가 없는 짧은 낮잠은 `Sip 추정`으로 분리한다.
- Sip은 Apple 알고리즘을 복제했다고 표현하지 않는다.
- 짧은 낮잠에 수면 단계를 생성하거나 의료적 품질 점수를 붙이지 않는다.
- 수면 신호가 부분적이면 구간과 출처를 표시하고 사용자가 수정할 수 있게 한다.

### 4.3 공개 API 실행 제약

watchOS Smart Alarm extended runtime session은 예약 실행이 가능하지만 최대 30분이며 한 번에 하나만 예약할 수 있고 다음 36시간 안에서 예약해야 한다. 따라서 60분의 낮잠 가능 시간대 전체에서 앱이 임의 센서를 계속 점유한다고 약속할 수 없다.

제품 동작은 다음처럼 분리한다.

- `낮잠 가능 시간대`: 사용자가 제공하는 관찰 문맥
- `종료 알람 켜짐`: 종료 전 최대 30분 Smart Alarm 세션을 활용하는 강화 구간
- `종료 알람 꺼짐`: 알람 없이 가용 신호와 사후 Apple 건강 결과를 병합
- HealthKit observer: 데이터가 저장된 뒤 변경을 감지하는 경로이며 실시간 수면 판정기로 취급하지 않음

## 5. 핵심 사용자 흐름

### 5.1 최초 설정

1. 앱이 실제 잠든 시간과 기상 후 상태를 기록한다는 목적을 설명한다.
2. Apple 건강, 동작·심박, 알림 권한을 각각 설명하고 선택받는다.
3. 권한을 거부해도 설정과 수동 수정 흐름을 계속 사용할 수 있다.

### 5.2 낮잠 가능 시간대

1. 사용자가 시작·종료 시각과 반복 요일을 정한다.
2. 종료 시각에 알람을 울릴지 선택한다.
3. 시간대는 수면 목표나 권장 시간이 아니라 `잠들 수 있는 범위`로 표시한다.
4. 저장 후 홈에는 시간대와 알람 여부만 간결하게 표시한다.

### 5.3 자동 기록

1. 시간대가 시작되면 Sip은 사용할 수 있는 신호를 확인한다.
2. 수면 가능성이 임계 기준을 넘을 때만 임시 `NapSession`을 만든다.
3. 종료 알람이 켜져 있으면 지원 범위에서 종료 전 Smart Alarm 세션을 실행한다.
4. 사용자가 Watch에서 오른쪽에서 왼쪽으로 스와이프하면 종료 확인 화면이 나타난다.
5. 수면 신호가 없으면 세션을 만들지 않고 `잠든 기록 없음` 상태를 보여준다.

### 5.4 결과 병합

1. 기상 또는 시간대 종료 뒤 Apple 건강 수면 샘플을 조회한다.
2. 샘플이 있으면 시간 구간과 중복을 조정해 병합한다.
3. 없으면 Sip 추정 또는 신호 부족 상태로 유지한다.
4. 사용자는 시작·종료 시각을 수정하거나 기록을 추가·제외할 수 있다.

### 5.5 기상 후 상태와 추세

1. 에너지·집중·기분을 숫자 없는 슬라이더로 기록한다.
2. 결과 화면은 실제 잠든 시간, 신호 타임라인과 출처를 먼저 보여준다.
3. 추세 화면은 잠든 시간, 수면 흐름과 기상 후 상태를 부드러운 곡선으로 보여준다.
4. 인과관계나 유지 효과를 단정하는 문구는 사용하지 않는다.

## 6. 낮잠 감지 모델

### 6.1 입력 신호

- Apple 건강 수면 샘플과 출처
- Apple Watch에서 공개 API로 사용할 수 있는 동작 신호
- 공개 API와 권한이 허용하는 심박 신호
- 낮잠 가능 시간대, 알람 설정과 사용자의 직접 종료
- 사용자가 수정한 실제 시작·종료 시각

### 6.2 처리 단계

1. 모든 신호를 절대 시각과 알고리즘 버전으로 정규화한다.
2. 짧은 움직임 변화만으로 수면을 확정하지 않고 연속 구간을 평가한다.
3. 검증된 임계 기준을 넘을 때 임시 구간을 생성한다.
4. Apple 건강 결과가 들어오면 중복 제거 후 우선 출처로 병합한다.
5. 신호가 상충하거나 부족하면 `부분 신호`로 남긴다.
6. 사용자 수정은 원본 신호를 삭제하지 않고 별도 보정으로 보존한다.

임계값, 최소 연속 시간과 신뢰 구간은 실제 기기 데이터 검증 전 확정하지 않는다.

### 6.3 수면 질 표현

단일 품질 점수 대신 다음을 분리해 보여준다.

- 실제 잠든 시간과 지속 시간
- 잠든 것으로 판단한 구간의 연속성
- 깨어 있음으로 보이는 구간 또는 신호 공백
- 측정 출처와 신호 충분성
- 사용자가 남긴 기상 후 상태

Apple 건강이 제공한 단계만 단계명으로 표시한다. Sip 추정에는 `깊은 수면`, `REM` 같은 단계명을 붙이지 않는다.

## 7. 상태 슬라이더

에너지·집중·기분은 내부적으로 `Float 0...1`로 저장하며 사용자에게 숫자를 노출하지 않는다.

| 항목 | 왼쪽 의미 | 오른쪽 의미 | 기본 시각색 |
| --- | --- | --- | --- |
| 에너지 | 기운이 없어요 | 활력이 있어요 | 주황 |
| 집중 | 흐릿해요 | 또렷해요 | 인디고 |
| 기분 | 불편해요 | 편안해요 | 분홍 |

- thumb 위치, 끝 의미, 햅틱과 VoiceOver 값으로 현재 상태를 전달한다.
- 색만으로 상태를 구분하지 않는다.
- 드래그 중 손가락을 즉시 따르고 놓은 뒤 0.25초 이하의 gentle spring으로 안정된다.
- `나중에`를 제공하고 입력을 강요하지 않는다.
- 추세에서는 원시 숫자 대신 선의 방향과 색, 기간 레이블을 제공한다.

## 8. 화면 구조

### iPhone

- 온보딩 · 자동 기록 원칙
- 권한 · 필요한 데이터만
- 홈 · 오늘의 시간대와 최근 낮잠
- 낮잠 시간대 설정
- 시간대 진행 중
- 기상 후 상태
- 낮잠 상세 · 실제 시간, 신호, 출처
- 낮잠 추세
- 잠든 기록 없음
- 설정 · 시간대, 알람, 권한, 내보내기

메인 탭은 Apple의 Liquid Glass 특성을 따르는 네이티브 탭바로 구성한다. Liquid Glass를 제공하지 않는 지원 OS에서는 네이티브 material 기반 폴백을 사용한다. 브랜드 `#373F7B`는 선택·강조에 사용하고 모든 배경이나 요소에 일괄 적용하지 않는다.

### Apple Watch

- 낮잠 시간대 예정
- 측정 중 · 첫 페이지
- 종료 확인 · 오른쪽에서 왼쪽 스와이프
- 종료 알람
- 완료

타이머는 링 안에 배치한다. 1시간 전에는 `mm:ss`, 1시간 이후에는 `hh:mm` 형식을 사용한다. 종료 확인은 `종료` 버튼만 제공하고 페이지 인디케이터는 버튼 아래에 둔다. 전송 완료·연결 대기 같은 내부 상태 문구는 기본 화면에서 제거한다.

## 9. 적응형 레이아웃과 접근성

- 기준 iPhone: iPhone 13 mini `375×812`
- QA iPhone: iPhone SE `375×667`, iPhone 15 Pro `393×852`
- 기준 Watch: 40mm `162×197`
- QA Watch: 45mm `198×242`
- iPhone 핵심 동작은 최소 44pt, Watch 핵심 동작은 최소 44pt를 확보한다.
- Dynamic Type 확대 시 세로 스크롤과 고정 하단 동작을 사용한다.
- VoiceOver 순서는 제목, 시간대, 알람 상태, 주요 동작 순으로 구성한다.
- Reduce Motion에서는 이동 스프링을 짧은 dissolve로 대체한다.
- 반복 애니메이션은 상태 전달에 필요한 경우만 사용한다.

## 11. 데이터 모델

### NapOpportunityWindow

`id`, `startLocalTime`, `endLocalTime`, `repeatWeekdays`, `alarmEnabled`, `timeZoneIdentifier`, `isEnabled`, `createdAt`, `updatedAt`

### NapDetectionEvidence

`id`, `windowId`, `observedStart`, `observedEnd`, `motionSegments`, `heartRateAvailability`, `healthKitSampleIdentifiers`, `source(appleHealth/sipEstimate/partial)`, `signalSufficiency`, `algorithmVersion`, `capturedAt`

### NapSession

`id`, `windowId`, `detectedStart`, `detectedEnd`, `actualDuration`, `source`, `signalSufficiency`, `userEdited`, `status(provisional/confirmed/excluded)`, `createdAt`, `updatedAt`

### ConditionCheckIn

`id`, `napSessionId`, `energy`, `focus`, `mood`, `recordedAt`, `updatedAt`

각 상태 값은 `0...1` 범위로 검증한다. 표시용 숫자나 파생 점수는 저장하지 않는다.

## 12. 알림

- 종료 알람은 시간대별로 사용자가 명시적으로 켠 경우에만 울린다.
- 시간대가 시작됐다는 알림은 기본값으로 강제하지 않는다.
- 기상 후 상태 리마인드는 개별적으로 끌 수 있다.
- 반복적인 미응답을 이유로 빈도를 자동으로 높이지 않는다.
- 동기화·전송 완료 같은 내부 상태는 성공 알림으로 노출하지 않는다.

## 13. 개인정보와 안전

- 건강·상태 데이터는 가능한 기기에서 처리한다.
- 서버 동기화 도입 전 저장 목적, 보존 기간, 암호화와 삭제 정책을 별도 결정한다.
- 민감한 원시 신호와 식별자를 분석 로그에 남기지 않는다.
- 사용자는 시간대, 세션, 상태 입력과 파생 추세를 삭제할 수 있다.
- Sip 추정을 Apple이 측정한 수면 단계처럼 HealthKit에 기록하지 않는다.
- 진단, 치료, 질환 예측과 약물 조언을 제공하지 않는다.

## 14. 성공 지표

| 지표 | 정의 |
| --- | --- |
| 감지 정밀도 | 사용자가 실제 낮잠으로 확인한 자동 감지 세션의 비율 |
| 감지 재현율 | 사용자가 실제 잤다고 확인한 낮잠 중 자동으로 발견한 비율 |
| 시간 오차 | 사용자 보정 시각과 감지 시작·종료 시각 차이의 중앙값 |
| 수정률 | 자동 생성 세션 중 사용자가 시간 또는 포함 여부를 수정한 비율 |
| 출처 이해도 | 사용자가 Apple 건강과 Sip 추정을 구분해 이해한 비율 |
| 상태 입력 완료율 | 확인된 세션 중 기상 후 세 상태가 기록된 비율 |
| 기록 유실률 | 어느 기기에도 복구 가능한 원본이 없는 비율 |

출시 전 수치 목표를 임의로 정하지 않는다. 실제 기기 파일럿으로 기준선을 확보한 뒤 코호트별 목표와 오탐 허용 기준을 확정한다.

## 15. 출시 인수 조건

- [ ] 낮잠 가능 시간대와 종료 알람 여부를 설정할 수 있다.
- [ ] 시간대 전체를 실제 수면으로 저장하지 않는다.
- [ ] 수면 신호가 충분할 때만 임시 세션을 만든다.
- [ ] Apple 건강, Sip 추정과 부분 신호가 구분된다.
- [ ] 기록 없음 상태에서 추가·수정 경로를 제공한다.
- [ ] 기상 후 세 상태를 숫자 없는 슬라이더로 기록할 수 있다.
- [ ] 상세 화면에서 실제 잠든 시간과 신호 타임라인을 확인할 수 있다.
- [ ] 추세 화면은 단일 품질 점수와 근거 없는 효과 문구를 사용하지 않는다.
- [ ] Watch 타이머, 스와이프 종료와 페이지 인디케이터가 설계대로 동작한다.
- [ ] 권한 거부, Watch 미사용, 오프라인과 재연결을 처리한다.
- [ ] 실제 Watch에서 Smart Alarm 예약·실행·취소 한계를 검증한다.
- [ ] VoiceOver, Dynamic Type, Reduce Motion과 최소 터치 영역을 검증한다.

## 16. 검증 계획

### 자동 검증

- 시간대, 반복 요일, 시간대 변경과 자정 경계
- `0...1` 상태 값 검증과 숫자 비노출
- 감지 구간 병합, 중복 제거와 사용자 보정
- Apple 건강 결과 지연 도착과 출처 우선순위
- Watch 로컬 저장, 재시도와 멱등 수신
- 기록 없음, 부분 신호, 권한 거부 상태

### 실제 기기 검증

- iPhone 13 mini·SE·15 Pro 레이아웃
- Watch 40mm·45mm 레이아웃과 화면 꺼짐
- 알람 켜짐·꺼짐, 예약·취소와 30분 제한
- Apple 건강 권한 허용·거부·부분 허용·변경
- 1시간 미만, 1–3시간, 3시간 초과 샘플 병합
- 연결 끊김, 앱 종료, 재실행, 재연결과 저전력
- 실제 낮잠 라벨과 비교한 오탐·미탐·시간 오차

시뮬레이터나 빌드 성공은 수면 감지, HealthKit 결과, Watch 백그라운드 실행과 알람의 실제 동작을 증명하지 않는다.
